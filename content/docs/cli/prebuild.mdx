---
title: prebuild
description: Generate native projects and apply the Expo app configuration.
---

```npm
npx expo-desktop prebuild [options]
```

Run this command from the app root. It copies missing native project folders from a template, updates dependencies when necessary, and applies app configuration and config plugins to the selected native projects. Existing folders are updated in place unless `--clean` is supplied.

```npm
npx expo-desktop prebuild --platform desktop
npx expo-desktop prebuild --platform macos --clean
npx expo-desktop prebuild --platform windows --no-install
```

## Options

| Option                                   | Default                                                 | Description                                                                                                                                                                |
| ---------------------------------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--platform <platform>`, `-p <platform>` | All four native platforms in the current implementation | Select `ios`, `android`, `mobile`, `macos`, `windows`, `desktop`, or `all`. See [platform selection](#platform-selection).                                                 |
| `--clean`                                | Off                                                     | Delete the selected native project folders before regenerating them. The command checks Git status and may ask before proceeding. Commit or preserve native changes first. |
| `--no-install`                           | Off                                                     | Skip dependency installation and CocoaPods installation. Native generation, dependency edits, and config plugins still run.                                                |
| `--npm`                                  | Off                                                     | Accept the npm package manager option. See the current [installation limitation](#dependency-installation).                                                                |
| `--yarn`                                 | Off                                                     | Accept the Yarn package manager option. See the current installation limitation.                                                                                           |
| `--bun`                                  | Off                                                     | Accept the Bun package manager option. See the current installation limitation.                                                                                            |
| `--pnpm`                                 | Off                                                     | Accept the pnpm package manager option. See the current installation limitation.                                                                                           |
| `--template <source>`                    | Resolved bare-minimum template                          | Override the native template with an npm spec, local npm tarball, or GitHub repository. See [templates](#templates).                                                       |
| `--skip-dependency-update`               | Off                                                     | Advertised as preserving a comma-separated list of dependency versions, but currently ineffective because the CLI declares it as a boolean. See the limitation below.      |
| `--help`, `-h`                           | —                                                       | Show command help.                                                                                                                                                         |

## Platform selection

| Value     | Native projects requested        |
| --------- | -------------------------------- |
| `ios`     | iOS                              |
| `android` | Android                          |
| `mobile`  | iOS and Android                  |
| `macos`   | macOS                            |
| `windows` | Windows                          |
| `desktop` | macOS and Windows                |
| `all`     | iOS, Android, macOS, and Windows |

The current help text says the default is `desktop`, but omitting `--platform` currently requests `all`. Pass `--platform desktop` explicitly for desktop-only generation.

If `expo.platforms` is configured, the CLI intersects the requested platforms with that list. If the intersection is empty, it warns and continues with the originally requested platforms. Web does not have a native project to prebuild.

On Windows, iOS and macOS generation is skipped. Requesting only those platforms leaves no valid platforms and causes an error. Generating a Windows project on another OS does not make it buildable there: [running Windows](/cli/run-windows) requires Windows, and [running macOS](/cli/run-macos) requires macOS.

## Dependency installation

Prebuild may update `package.json` to match the template. When dependencies change and installation is enabled, it asks whether to install them. CocoaPods installation runs for selected Apple projects when new native files or dependency changes require it.

The package manager options are accepted and checked for conflicting selections when installation is enabled. However, the selected value is not currently passed to the dependency installer. Installation uses `npm_config_user_agent`, then the available package manager fallback described in the [create-app reference](/cli/create-app#prompts-and-package-managers). Do not rely on the help text's lockfile-based defaults or these flags to force a manager in this version.

The help text also presents `--skip-dependency-update` as a string option, but its argument definition is boolean and its resolver only accepts strings. Neither the bare flag nor the advertised comma-separated form reliably preserves dependency versions. Review `package.json` changes after prebuild rather than relying on this option.

## Templates

Without `--template`, prebuild first tries the Expo Desktop source template when running from its monorepo, then an installed `expo-desktop-template-bare-minimum` dependency relative to the app. It falls back to downloading that package for the Expo SDK major, or `@latest` when the SDK version is unspecified.

```npm
npx expo-desktop prebuild --platform desktop \
  --template expo-desktop-template-bare-minimum@55.83.9

npx expo-desktop prebuild --platform desktop \
  --template ./expo-desktop-template-bare-minimum.tgz
```

A local template must be a tarball, normally created with `npm pack`. GitHub sources can use `owner/repo` shorthand or a full `https://github.com/owner/repo/tree/ref/path` URL. The repository must contain a suitable project template. Other HTTP repository hosts are not supported by the prebuild downloader.

Source: [prebuild implementation](https://github.com/shirakaba/expo-desktop/tree/main/packages/expo-desktop/src/prebuild).
