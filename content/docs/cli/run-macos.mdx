---
title: run macos
description: Build and launch an Expo Desktop app on macOS.
---

```sh
npx expo-desktop run macos [project-root] [options]
```

Requires macOS with Xcode and the app's native dependencies installed. The target is always the current Mac; there is no device or simulator selector. If the `macos` folder is missing, the command attempts to prebuild it first.

```sh
npx expo-desktop run macos
npx expo-desktop run macos --configuration Release --no-bundler --output ./dist/macos
```

The default Debug build loads JavaScript from Metro. A Release build bundles JavaScript and assets into the app before the native build. The command launches the resulting app, including when `--output` is provided. There is no macOS `--no-launch` option.

## Argument

| Argument       | Default           | Description                                                                                                                                                                         |
| -------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project-root` | Current directory | Path to the app project, resolved relative to the current directory. Run from the app root if automatic prebuild is needed, because that step currently uses the working directory. |

## Options

| Option                   | Default                       | Description                                                                                                                                                                                                     |
| ------------------------ | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--configuration <name>` | `Debug`                       | Xcode build configuration. Use `Release` for a production JavaScript bundle. Custom Xcode configuration names are passed through, but only the exact name `Release` selects the CLI's production bundling path. |
| `--scheme <name>`        | Inferred macOS app scheme     | Select the Xcode scheme. The CLI prefers `<project>-macOS`, then the only available scheme, then a scheme containing `macos`.                                                                                   |
| `--no-build-cache`       | Off                           | Run Xcode's `clean` action before `build` instead of reusing its normal native build output. This does not clear Metro's cache.                                                                                 |
| `--no-install`           | Off                           | Skip installation during automatic prebuild and skip the CocoaPods synchronization prompt for an existing project. Required dependencies must already be installed.                                             |
| `--no-bundler`           | Off                           | Request that no Metro server be started. See the [Debug limitation](#metro-behavior).                                                                                                                           |
| `--port <port>`          | `RCT_METRO_PORT`, then `8081` | Select the Metro port; `0` chooses an available port. Valid range is `0`–`65535`. Cannot be combined with `--no-bundler`.                                                                                       |
| `--binary <path>`        | Build the app                 | Open an existing `.app` bundle instead of compiling a new one. The path must exist and end in `.app`. Native project and dependency setup still runs.                                                           |
| `--output <directory>`   | No copy                       | Copy the built or supplied `.app` into this directory and launch the copy. The directory is created if needed.                                                                                                  |
| `--background`           | Off                           | Launch the app without bringing it to the foreground.                                                                                                                                                           |
| `--no-single-instance`   | Off                           | Launch a new app instance. By default, the command terminates existing instances with the same bundle identifier before launching.                                                                              |
| `--help`, `-h`           | —                             | Show command help.                                                                                                                                                                                              |

## Metro behavior

The command reuses an already-running Metro server for this project on the selected port, including a server started with `npx expo start`. Otherwise it starts the app's Expo Metro server and developer interface, which can serve the app's configured mobile and Web targets as well.

In the current implementation, selecting `Debug` forces the bundler-start path even when `--no-bundler` was provided. An already-running server can still be detected and reused. For a standalone Release run without a persistent Metro server, explicitly use `--configuration Release --no-bundler`.

`--port` and `--no-bundler` are mutually exclusive even with a supplied `--binary`. See the [shared Metro reference](/cli#metro-and-environment) for port selection details.

## Reusing a binary

```sh
npx expo-desktop run macos \
  --configuration Release \
  --binary ./dist/macos/MyApp.app \
  --no-bundler
```

Use a configuration that matches the existing binary. `--configuration` does not change how a supplied binary was built.

### Experimental rebundling

`--unstable-rebundle` is an internal, experimental option, off by default. It requires `--binary`. It updates the embedded Expo app configuration and, if `Contents/Resources/main.jsbundle` exists, replaces the JavaScript bundle and assets in that app. The CLI warns that the operation may not work as expected.

Modifying a previously signed app invalidates its signature. Re-sign a modified binary before distributing it. Prefer a fresh Release build for distribution.
