---
title: run windows
description: Build, deploy, and launch an Expo Desktop app on Windows.
---

```npm
npx expo-desktop run windows [project-root] [options]
```

Requires Windows with Visual Studio and the React Native Windows development dependencies installed. The target is always the current Windows machine. If the `windows` folder is missing, the command attempts to prebuild it first.

```npm
npx expo-desktop run windows
npx expo-desktop run windows --configuration Release --no-launch --output ./dist/windows
```

A normal run performs autolinking, builds the app, starts or reuses Metro for development, then deploys and launches the app. Release builds use their embedded JavaScript bundle and do not start a persistent Metro server. `--no-launch` stops after building and exporting, without deploying the app or starting Metro.

## Argument

| Argument       | Default           | Description                                                                                                                                                                         |
| -------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project-root` | Current directory | Path to the app project, resolved relative to the current directory. Run from the app root if automatic prebuild is needed, because that step currently uses the working directory. |

## Options

| Option                        | Default                       | Description                                                                                                                                                                                                                         |
| ----------------------------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--configuration <name>`      | `Debug`                       | Native build configuration. Only `Debug` and `Release` are accepted, with this capitalization. `Release` selects the React Native Windows release bundling path.                                                                    |
| `--arch <architecture>`       | Detected host architecture    | Build `ARM64`, `x86`, or `x64`. Input is case-insensitive and normalized by React Native Windows. The default uses Node's architecture, with a correction for x86 Node on x64 Windows. Use native ARM64 Node for ARM64 development. |
| `--no-build-cache`            | Off                           | Clean the selected native solution, architecture, and configuration before building. Ignored when restoring an existing `--binary`. Does not clear Metro's cache.                                                                   |
| `--no-install`                | Off                           | Skip dependency installation during automatic prebuild. Dependencies must already be installed.                                                                                                                                     |
| `--no-bundler`                | Off                           | Request that no Metro server be started. See the [Debug limitation](#metro-behavior).                                                                                                                                               |
| `--port <port>`               | `RCT_METRO_PORT`, then `8081` | Select Metro's port; `0` chooses an available port. Valid range is `0`–`65535`. Cannot be combined with `--no-bundler`.                                                                                                             |
| `--binary <directory>`        | Build the app                 | Restore existing Windows build artifacts instead of compiling. Accepts a native `windows` directory or a directory previously produced with `--output`. See [artifact reuse](#artifact-reuse).                                      |
| `--output <directory>`        | No export                     | Export the app layout and package artifacts into this directory. The exported directory can later be passed to `--binary`.                                                                                                          |
| `--singleproc`                | Off                           | Disable multiprocess native builds.                                                                                                                                                                                                 |
| `--logging`                   | Off                           | Enable verbose React Native Windows CLI logging.                                                                                                                                                                                    |
| `--no-launch`                 | Off                           | Build or restore artifacts without deploying or launching the app. This also avoids starting Metro and the developer interface.                                                                                                     |
| `--no-autolink`               | Off                           | Skip Windows autolinking. By default, autolinking runs before either building or restoring artifacts.                                                                                                                               |
| `--msbuildprops <properties>` | None                          | Pass a comma-separated list of MSBuild properties, such as `AppxPackageSigningEnabled=false,AppxBundle=Never`.                                                                                                                      |
| `--direct-debugging <port>`   | Off                           | Enable the React Native Windows direct debugging mode on the given port. Accepted range is `1024`–`65534`; this is separate from Metro's port.                                                                                      |
| `--no-telemetry`              | Off                           | Disable usage and failure telemetry from the React Native Windows CLI for this command.                                                                                                                                             |
| `--help`, `-h`                | —                             | Show command help.                                                                                                                                                                                                                  |

Expo Desktop resolves the solution and app project automatically. React Native Windows CLI flags such as `--release`, `--bundle`, `--sln`, `--proj`, `--device`, `--emulator`, `--no-build`, and `--no-deploy` are not Expo Desktop CLI options. Use `--configuration Release`, `--binary`, and `--no-launch` for the corresponding supported workflows.

## Metro behavior

Development runs reuse an already-running Metro server for this project on the selected port, including one started with `npx expo start`. Otherwise they start the app's Expo Metro server and developer interface. That server can also serve the configured iOS, Android, and Web targets.

In the current implementation, selecting `Debug` forces the bundler-start path even when `--no-bundler` was provided. Existing Metro servers can still be detected and reused. Release and `--no-launch` runs do not start a persistent Metro server.

The CLI selects Metro's port and passes the chosen value through `RCT_METRO_PORT`. Support for a non-default port also depends on the native React Native Windows version and template. If the native app still requests `8081`, use the default port or update its native Metro configuration. See the [shared Metro reference](/cli#metro-and-environment) for port selection details.

## Artifact reuse

```npm
npx expo-desktop run windows \
  --configuration Release \
  --arch x64 \
  --no-launch \
  --output ./dist/windows

npx expo-desktop run windows \
  --configuration Release \
  --arch x64 \
  --binary ./dist/windows
```

`--binary` is a directory of build output, rather than an `.exe` or an individual MSIX/AppX file. It must contain both the loose app layout and `MyApp.Package/AppPackages`. The expected layout is `<arch>/<configuration>` for x64 and ARM64, and `<configuration>` for x86. The command copies these artifacts into the current project's `windows` directory before deployment.

Pass the same architecture and configuration used for the original build. Native project setup and autolinking still run unless disabled; exported artifacts do not replace the app's project or JavaScript dependencies. The export contains the artifacts needed by React Native Windows to deploy the app, and is not itself a store submission command.
