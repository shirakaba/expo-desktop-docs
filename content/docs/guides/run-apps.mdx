To build and run your app for any platform, run any of the following commands:

```npm
# These commands use the Expo CLI:
node --run ios
node --run android
node --run web

# These commands use the Expo Desktop CLI:
node --run macos
node --run windows
```

The Expo Desktop CLI commands are broadly used the same way as the [`expo run:ios` and `expo run:android`](https://docs.expo.dev/more/expo-cli/#building).

## Common arguments

- `--no-build-cache`: Clear the native cache before building. On macOS, this is the **derived data** directory. Cache clearing is useful for profiling your build times.
- `--no-install`: Skip installing dependencies. On macOS, this will also skip running `npx pod-install` if the `dependencies` field in the project's `package.json` has changed.
- `--no-bundler`: Skip starting the dev server. Enabled automatically if the dev server is already serving the app from a different process.
- `-o, --output <path>`: Directory to copy the built app binary to after the build completes. Useful for CI/CD pipelines or when you want the binary in a predictable location.
- `-p, --port <port>`: Port to start the development server. **Default: 8081**. This is only relevant for development builds. Production builds will [export](#exporting) the project and embed the files in the native binary before installing them on a device.
- `--binary <path>`: File path to the binary to install on the device. When this is provided, the build process will be skipped and the binary will attempt to be installed directly. If the binary was not built for the correct device, for example, it is built for the simulator or installed on the device, then the command will fail.

## Compiling macOS

A macOS app can have multiple **schemes** for representing different sub-apps like App Clips, watchOS apps, Safari Extensions, and so on. By default, `node --run macos` will automatically choose the scheme for your macOS app. You can pick a custom scheme with the `--scheme <my-scheme>` argument. If you pass in the `--scheme` argument alone, then Expo CLI will prompt you to choose a scheme from the list of available options in your Xcode project.

You can compile a macOS app for production by running:

```sh
node --run macos -- --configuration Release
```

This build is not automatically code signed for submission to the Apple App Store. `node --run macos` should mostly be used to test bugs that only show up in production builds.

You can debug using `lldb` and all of the native Apple debugging tools by opening the project in Xcode and rebuilding from Xcode:

```sh
xed macos
```

Building from Xcode is useful because you can set native breakpoints and profile any part of the application. Be sure to track changes in source control (git) in case you need to regenerate the native app with `node --run prebuild -- --platform macos --clean`.

## Compiling Windows

You can compile a Windows app for production by running:

```sh
node --run windows -- --configuration Release
```

This build is not automatically code signed for submission to the Windows Store. `node --run windows` should mostly be used to test bugs that only show up in production builds.

You can debug using Visual Studio 2026, by attaching to the process.

Building from Visual Studio is useful because you can set native breakpoints and profile any part of the application. Be sure to track changes in source control (git) in case you need to regenerate the native app with `node --run prebuild -- --platform windows --clean`.
